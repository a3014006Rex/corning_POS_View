# TC 變更複查

以 [AGENTS.md](../../../AGENTS.md)、本次需求、實際差異與相關契約作為基準。使用者只要求審查時回報問題；若是已授權開發的收尾，補齊必要漏項，不擴大為無關的全庫重構。

## 第一輪：可觀察行為

按變更選擇核對：

- API 路由、HTTP 狀態與 camelCase envelope；HTTP 200 的業務失敗、格式錯誤與 traceId 能否被前端辨識。
- 頁面載入、空資料、失敗、取消、舊回應與重複送出。卸載時清理請求及計時器。
- 本機設定不冒充授權餐道。新增業務 API 受後端授權與資料範圍控制，公開端點有明確用途；不將預覽模式當成正式功能。
- 涉及 POS 交易時依 `tc-pos-transactions` 核對固定交易 ID、查單、跨餐道與個資清除，不因按鈕已停用就推定後端完成去重。
- 設定、文件、範例與 Git 差異不包含實際卡號、連線密碼、金鑰或客戶 DB 內容。

## 第二輪：證據與交接

依 AGENTS.md 執行受影響的 build／lint／測試。新變更或失敗才重跑相關檢查；不要用與實作同義的斷言取代行為驗證。

文件／Skills 核對相對連結、實際路徑、frontmatter、描述觸發範圍與支援資源；有驗證器時執行。僅寫好檔案不能宣稱當前工具已自動載入新 Skill。

更新受影響的 API／畫面契約、工作追蹤與執行方式，保留既有紀錄。清楚區分「骨架可建置」「示範可操作」「真實 API／DB 通過」「設備通過」「客戶 UAT」。缺少環境或證據時如實列未測，不能將 A01–A39 改為通過。
