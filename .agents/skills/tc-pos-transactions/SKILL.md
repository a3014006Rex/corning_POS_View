# TC POS 交易流程

根據實際修改讀取 [API 契約 E14–E21](../../../Document/康寧餐卡POS開發/3_設計與契約/TC_API契約.md#e14)、[業務規則與狀態契約](../../../Document/康寧餐卡POS開發/3_設計與契約/TC_業務規則與狀態契約.md) 與 [Q 決策](../../../Document/康寧餐卡POS開發/1_RA與流程圖/TC_RA問題確認.md)。它們是規劃草案；以有來源的後續核准決策更新，不把暫定規則當成客戶同意。

## 不可混淆的對象

- 設備原始事件、POS Claim、Quote、ClientTransactionId 與正式 TransactionId 分開追蹤。讀到卡號、取得資格或設備蜂鳴都不是記帳完成。
- 設備重傳、同人再次刷卡、同交易網路重試是三種不同情境。正式提交的重試沿用原 ClientTransactionId，相同 ID 不同內容回衝突。
- 新刷卡不能覆蓋尚未完成的當事人。完成、取消或政策逾時後清除姓名與其他上一人資料；交易恢復只保存必要且受保護的查單資訊。
- 卡號是字串並保留前導零；顯示按權限遮罩，不以截斷卡號推定身分。刷卡自然日、設備時間與營業歸屬日分開。

## 提交與失敗

服務端負責資格、當時指派、餐別、報價、分攤與授權餐道。前端金額轉最小貨幣單位時檢查安全整數及正式業務上限；公司／DL／自付分攤以核准案例確認。

同一 SQL 交易涵蓋去重、Claim／Quote、消費、分攤、權益占用及 Outbox。補助按員工／權益範圍控制併發，不按卡號獨立發放。

回應逾時顯示「結果待確認」，先以原 ID 查單。重新整理或重啟不得直接建立另一筆交易；通用 HTTP client 不自動重送提交。未選定離線政策前不新增離線授權。取消／沖正保留原帳、原因、授權及調整關聯；外部支付依 Q08 另有查單和補償。

## 驗證範圍

選擇與變更有關的 A16–A26、A34 案例，至少核對受影響的正常、拒絕、重試與邊界。分別記錄模擬、SQL 併發、實體設備與 UAT 的實際結果；設備規格未到位時不猜解析器或宣告實測成功。
