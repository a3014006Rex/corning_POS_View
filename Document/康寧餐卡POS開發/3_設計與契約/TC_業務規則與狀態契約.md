## 2. 事件與領取

| 目前 | 動作 | 下一狀態 | 條件 |
|---|---|---|---|
| RECEIVED | 解析/驗證成功 | AVAILABLE | 保存原始事件與來源鍵；未知格式列異常 |
| AVAILABLE | POS 領取 | CLAIMED | 正確終端、餐道、單一有效租約 |
| CLAIMED | 提交交易 | CONSUMED | Claim、Quote 與資格通過，與交易一起提交 |
| CLAIMED | 未提交前釋放/到期 | AVAILABLE 或 EXPIRED | 依 Q02 設定可重領策略，不能同時給兩筆交易 |
| 任意 | 收到同來源事件重傳 | 既有狀態 | 回原接收結果；不可重建另一事件計費 |


事件過期、消耗與原始資料刪除是不同事情；原始證據留存依 Q12。

## 3. 草稿、正式交易與沖正

| 對象/目前 | 動作 | 結果 | 限制 |
|---|---|---|---|
| 草稿 DRAFT | 取消/逾時 | ABANDONED | 沒有正式費用；保存操作與釋放領取 |
| 草稿 DRAFT | 確認並提交 | 正式交易 COMMITTED | 原子保存結果，COMMITTED 後金額不直接修改 |
| 正式交易 COMMITTED | 完整沖正 | REVERSED＋反向分攤 | 權限、原因與獨立操作 ID；補助回補依 Q07 |
| 已沖正交易 | 恢復/更正申請 | 新草稿或核准恢復策略 | Q07 未定前不啟用；原帳與沖正均保留 |
| 已結算交易 | 取消/更正 | 調整項 | 已確認結算批次不直接重算 |
| 未知回應 | 原 ID 查單 | 查得 COMMITTED/REVERSED/仍處理中/確定未受理 | UNKNOWN 是客戶端觀測結果，不新增一筆未知費用 |


一期估算以完整沖正為基準；若需部分退款、跨期多次調整或卡片內退款，納入 Q07/Q08 後另補契約與估算。

## 4. 同步與工作狀態

PENDING → PROCESSING → SUCCEEDED；暫時失敗 → RETRY_WAIT → PROCESSING；超過條件或不可恢復 → MANUAL_REVIEW。保留嘗試、最後錯誤與確認點；人工結案需原因與證據，不直接把待處理狀態改成成功。

## 5. 並行與變更

同一事件領取、同交易提交、同補助桶、同卡有效期間、同結算項目均以資料庫唯一性或版本/鎖定保護。所有「先查是否有，再寫入」都必須考慮第二個請求同時通過的情境。

報價後卡片撤銷、規則或營業日判斷改變時重新驗證；若尚未提交需重報價並確認。已提交的同 ID 重試則回原結果，避免期限或設定變更把成功結果改成失敗。
