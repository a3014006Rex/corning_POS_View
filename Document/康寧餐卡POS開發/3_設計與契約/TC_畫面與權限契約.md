## 2. 一期主要畫面欄位與操作

| 畫面群 | 必要欄位 | 必要操作與狀態 |
|---|---|---|
| 員工與組織 | 員編、姓名、類別、部門、工作地點、在職、生效版本及來源 | 查詢、預檢匯入、查看異動；不可靜默截斷 |
| 正式/臨時卡 | 原始/正規卡碼（依權限遮罩）、持卡人、有效起迄、掛失/歸還、設備同步狀態 | 指派、換卡、撤銷、借還與查歷程；不可覆蓋舊交易歸屬 |
| 餐別與補助 | 時段、跨日、營業日、資格期間、公司/DL/自付、規則版與生效時間 | 編輯草稿、驗算核准案例、發布；已發布版不可直接改 |
| 設備與餐道 | 型號韌體、來源 ID、餐道/POS 對應、最後有效事件、解析錯誤、積壓 | 啟停/設定依權限；名單同步、銷碼與結果；全量重設受控 |
| POS 主畫面 | 餐道、員工、卡片末碼、資格原因、餐別、營業日、金額及分攤 | 領取、輸入金額、確認、取消草稿、查單；新刷卡不覆蓋當前人 |
| POS 結果 | 交易 ID、記帳結果、時間、金額、失敗原因或待確認狀態 | 保留原 ID 重試/查單；完成或取消後清除上一人個資 |
| 交易明細/補登 | 來源事件、指派、規則快照、分攤、狀態、操作者、證據、沖正關聯 | 受權限補登/沖正/更正，原因與結果可追溯 |
| 異常/同步 | 類型、來源、重試、版本、錯誤、處置人與時間 | 重試、補證據、結案；不允許刪異常掩蓋帳差 |
| 報表/結算 | 營業日、員工/餐道/廠商、有效狀態、各分攤、批次與差額 | 查詢、匯出、建立/確認結算、調整；已確認批次唯讀 |


## 3. 權限矩陣

以下是角色能力提案；實際職稱、一人多角、主管分權與來源帳號依 Q11 確認。所有資料範圍都由後端檢查。

| 能力 | POS | 餐務/卡務 | 財務 | 維運 | 管理者 | 稽核唯讀 |
|---|---|---|---|---|---|---|
| 領取事件與提交本人餐道交易 | 授權餐道 | 否 | 否 | 否 | 不因管理者而自動取得裝置身分 | 否 |
| 員工/卡務維護 | 否 | 授權範圍 | 查詢 | 僅同步狀態 | 依授權 | 遮罩查詢 |

| 補登/沖正 | 否或另授權 | 依核准職責 | 依核准職責 | 否 | 依授權 | 唯讀 |
| 報表/匯出/結算 | 僅本機結果 | 授權範圍 | 授權範圍 | 否 | 依授權 | 核准範圍唯讀 |
| 設備設定/重試 | 僅自身狀態 | 依設備權限 | 否 | 授權範圍 | 依授權 | 唯讀 |
| 帳號與權限 | 否 | 否 | 否 | 不默認擁有 | 授權管理 | 唯讀 |

管理者、卡機裝置與 POS 服務身分應分開。按鈕隱藏不是權限保護；直接呼叫 API、猜交易 ID 或換 LaneId 仍應被拒。檔案下載與工作查詢同樣驗權，不因知道 FileRef 就能下載。

## 4. 操作與錯誤體驗

- POS 顯示「記帳完成」「結果待確認」「未受理／被拒絕」三種可理解結果；不以設備蜂鳴或 HTTP 回應即顯示成功。
- 提交中鎖定本筆的身分及確認內容；重試沿用原交易 ID。瀏覽器重整/程式重啟後先查單，不能丟失正在處理的 ID。
- 金額變更重新報價；前端可以提示但不能自己決定補助。
- 日期顯示實際刷卡日與營業歸屬日，避免午夜後讓操作人誤判。
- 匯入前預檢、批次執行狀態、可重試錯誤與需人工處理分開；全量清空卡名單需明確影響與維護條件。
- 完成、取消或操作閒置後，依政策清除上一人姓名/照片；畫面及匯出範圍依角色遮罩。
