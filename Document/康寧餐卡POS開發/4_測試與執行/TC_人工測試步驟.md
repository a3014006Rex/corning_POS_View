# TC 人工與整合測試步驟

版本 v1.0。A01–A36 為一期測試計畫，A37–A39 選配；全部尚未執行。實際測試結果填[驗收結果紀錄](TC_驗收結果紀錄.md)，不可在本文件預先勾通過。

## Step 0 測試前準備

1. 完成各案例相依工作與 Q 決策，使用[合成資料](TC_測試資料規格.md)，確認環境無正式扣款作用。
2. 依[執行與偵錯](TC_執行與偵錯步驟.md)確認實際 API、POS、Gateway、DB 與版本。未建立程式時本計畫不能執行。
3. 設備用隔離測試機；確認獨占、下載清除與 ACK 限制。禁止未確認就雙開舊/新接收器。
4. 業務規則測試以人工核准案例為準；模擬封包、原廠樣本與現場真實刷卡分別註明。
5. 每個案例均填預期、實際、證據、問題單與重測。失敗後先保存證據，不把失敗紀錄覆蓋成單一成功。

## Step 總覽

| 階段 | 案例 | 目的 |
|---|---|---|
| 基礎權限與資料 | A01–A09 | 人員、卡片、資格、餐期與對應 |
| 設備取樣與重播 | A10–A15 | 真實通訊、分框、補傳與下發 |
| POS 與交易 | A16–A26 | 多餐道、領取、報價、提交、查單與沖正 |
| 後台、報表與維運 | A27–A35 | 補登、異常、同步、統計、移轉及降級 |
| 完整餐期與切換 | A36 | 效能、UAT 與回復演練 |
| 選配 | A37–A39 | 菜單、訂單、供應與取餐 |

## 完成判定

一期適用案例逐一有證據；受阻不算通過，不適用需理由與確認者。模擬測試不能代替實體卡機，API 成功不能代替人工 POS 操作。A36 必須涵蓋核准的多餐道、尖峰、完整餐期與計費來源切換，帳差全部結清後才可提 UAT 完成。
