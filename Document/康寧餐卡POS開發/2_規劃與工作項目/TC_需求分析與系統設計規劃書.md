## 1. 開發目標與基線

建立員工刷卡辨識、POS 金額確認、用餐交易、餐補分攤、補登沖正、報表結算及卡片同步。支援多餐道且每筆交易可追溯來源事件、當時身分、餐別、規則與金額。

目前來源顯示舊後台以 PowerBuilder 執行檔/PBD 交付；C# 專案為 .NET 8 WinForms 的 TCP 診斷原型，尚未提供可確認的卡機解析、交易 API 與計費寫入。此規劃屬新平台開發及既有設備整合，不能按「全部已有，只補畫面」估算。

26 項一期建議與 3 項選配見[功能清單](../1_RA與流程圖/TC_需求與功能清單.md)。本次已確認新 POS 與新管理後台同批交付，但具體功能／權限及 TC-06 選配仍待逐項確認，沒有因此全部核准。

2026-11-08 條件：第一階段 1 台 Windows 11 POS，目前沒有另提供的新 API 主機；已有舊系統 DB，主檔來源待後續連線核對。以僅內網也可操作規劃，只記帳及匯出、財務另結算，不做當場收款／扣款。新系統接管切換後新增記帳，舊系統保留歷史查詢；一期暫不整合舊歷史消費至新後台。公司／DL／員工分攤仍待財務確認。

原始 HTML／CSS／JS 已歸入 [靜態畫面原型](../3_設計與契約/靜態畫面原型/README.md)，作為 Vue 版面參考，`pos_success.html` 是辨識後待確認。文件統一維護在根目錄 `Document`，來源檔仍在 `開發前規劃資料`。完整核對見 [前期安排](../../AI區/前期規劃核對與開發安排.md)。

## 3. 系統邊界與責任

- 卡機／控制器與原廠：提供可用接口、協定、測試樣本、金鑰／授權與設備操作限制。
- Gateway：版本化解析、可靠保存、確認點、重連與補傳、卡片同步命令。
- 核心 API：權威的卡片指派、資格、餐別、分攤、提交、去重、併發與沖正。
- POS：取得自身餐道事件、呈現身分與報價、確認、查單及受控降級。
- 管理後台：員工卡務、規則、補登、異常、權限、報表與結算。
- HR／財務／收款／廚房等外部接口：依 Q08/Q10/Q11 的正式契約納入。未提供接口不假設已具備。

第一期記帳模型不等同金流或卡片內扣款。若需外部支付，新增外部狀態、查單、補償與對帳，並調整範圍與工期。

## 4. 技術與資料設計原則

已採 ASP.NET Core .NET 10、Vue 3／Vite，SQL Server 與可在卡機網段執行的 Gateway 為目標。API／Vue／接收程式優先評估部署 POS；SQL 位置、設備 SDK 位元架構、POS 規格及正式託管仍待盤點，不因只有一台新 POS 就假設沒有既有 DB 主機。

先採單一核心 API 與資料庫，設備服務可獨立部署。前端透過 API；即時通知需有持久事件與重連補取，通知傳送成功不代表業務提交成功。具體設計見[架構](../3_設計與契約/TC_程式邏輯架構.md)、[資料模型](../3_設計與契約/TC_資料模型與移轉設計.md)。

## 5. 主線流程

設備事件保存與解碼 → 對應 POS 原子領取 → 取得身分／資格及服務端報價 → 確認 → 使用固定交易 ID 提交 → 同一資料庫交易保存消費、補助、去重與待同步事件 → 回傳結果 → 查詢、結算或沖正。

分開處理三種重複：設備重傳、同人再次刷卡、同交易網路重試。後兩者不能只靠卡號加秒數去重。跨餐道補助限制採員工／權益主體，不以卡號代替。

## 7. 開發工作與完成定義

[工作項目](TC_開發工作項目.md)列 T00–T35、依賴、估算、可先做部分與驗收。開發一次選擇依賴已完成的一張；文件完成、程式實作、設備實測與人工驗收分開標記。

## 8. 資源與排程情境

一期 RD 初估合計 120.5 人日；設備協定不確定，暫加 25% 風險額度為約 151 人日。另需 QA、PM、客戶與廠商投入，未包含等待、硬體採購、第三方開發及選配 15 RD 人日。

18 週情境假設設備/後端 2 名 RD、前端 1 名 RD，QA 0.5–1 名、PM/SA 約 0.3 名參與，輸入資料及測試設備依時到位。3 名 RD × 18 週 × 5 日 × 60% 可用開發工時約 162 人日，只是容量檢核，不保證未知協定可在固定時間解決。見[階段與排程](TC_階段與排程.md)。

## 9. 測試與上線

A01–A36 覆蓋一期；A37–A39 為選配。優先完成實體單餐道主線與查單，再擴多餐道、併發、補傳、補登、結算與移轉。模擬通過、實體設備通過、人工 UAT 簽認各留獨立證據。

正式切換前依[切換與回復計畫](../4_測試與執行/TC_切換上線與回復計畫.md)確保單一計費權威。新舊並行觀測不得同時產生正式費用，設備不允許多接收者時不能直接雙開。切回後，新平台已提交交易需有查單及對帳處理，不能只回復舊 DB 快照。
