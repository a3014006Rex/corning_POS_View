# TC Codex 開發執行指令

此檔供開始程式開發時使用。與 M10 的完成後反推 SASD 情境不同，本案目前屬前期規劃，不以虛構程式回填設計證據。

## 可直接使用的指令

你正在開發康寧餐卡與 POS 整合系統。請先讀此資料夾的 README、工作追蹤表、需求與功能清單、Q01–Q12、開發工作項目，以及所選工作對應的設計契約。

1. 先辨識實際工作區與 AGENTS.md，不使用其他專案的固定絕對路徑。未找到程式專案，先按 T04 建立本案骨架；不得假設 M10 的 API 或 Vue 元件存在於本案。
2. 從 T00–T35 中選一張所有依賴已完成的工作。優先順序：T01/T02/T03 的可執行部分與 T04。若使用者指定工作，先核對相依。
3. 回報本卡範圍、已確認規則、仍待 Q 決策及可以先完成的部分。未知設備封包不可猜測；合成與模擬結果要明確標示。
4. 追查實際來源檔案與接口。文件中的 E01–E42 均為提案；未找到實作時記待開發，不以文件名稱當實作證據。
5. 完成最小可驗證實作；身分、資料範圍、狀態、金額及去重由伺服器判斷。設備事件與交易分開，重試沿用同 ID，外部支付另有查單與沖正。
6. 涉及正式設備、還原/移轉/資料異動或部署時，先按本次已獲授權的環境與範圍執行；未有授權時先完成可審閱的腳本與回復設計。不得讀取或輸出不相關專案機密。
7. 執行適用 Build、規則/API 測試與實際設備/畫面驗證。沒有環境或腳本記為未測／受阻，不能寫通過。文件工作只做文件驗證，不需要假造 Build 紀錄。
8. 檢查半包黏包、雙餐道、同交易重送、提交後回應遺失、補助併發、跨午夜與取消的受影響案例。
9. 將實際版本、檔案、接口、指令、結果與限制回填工作項目、驗收結果紀錄及工作追蹤表；同步契約與資料模型。
10. 完成後回報：做了什麼、如何驗證、還缺什麼、下一張可開始的工作。未經指示不 Commit/Push、正式上線或對外通知。

## 單張工作輸入格式

- 目標工作：TC-Txx（例如 T04；確認當前依賴）。
- 環境：由目前實際工作區判斷，不預填正式 DB 或設備位址。
- 依據：本規劃目前版本與客戶已回覆決策。
- 交付：實作、必要測試、契約更新、可重現驗證紀錄與進度回填。
