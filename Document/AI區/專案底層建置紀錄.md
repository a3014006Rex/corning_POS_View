## 工程選擇

- .NET 10、ASP.NET Core Controller API、CommonLibrary 內分 Application／Domain／Infrastructure。MHC 同樣使用 net10.0；[官方支援政策](https://dotnet.microsoft.com/en-us/platform/support/policy/dotnet-core) 將 .NET 10 列為 LTS。
- Vue 3、JavaScript Composition API、Vite、Pinia、Vue Router Hash History、CoreUI；保留與 MHC 接近的工作方式。依實際 npm registry 與本機 Node 24.14.0 相容性選版本，使用 lockfile。
- API 使用本案 `/api/v1`、camelCase 回應；只借用 MHC 的分層與封裝概念，不搬入醫療業務、帳密、JWT 簽章設定、DB Context 或發布目錄。
- Vite 開發代理連本機 API；產物僅輸出 `SourceCode/Web/dist`，不清空 MHC 的外部發布目錄。
- 正式身分來源尚未確定。`PendingIdentityHandler` 拒絕受保護 API；系統資訊與程序存活明確公開。這是 T04 的暫時邊界，不將 T07 標為完成。
- SQL／Gateway 僅保留架構邊界，未建置實體接收服務、假 SQL 寫入或補助公式。

## 已建立能力

1. `GET /api/v1/system/info`：回應名稱、版本、UTC 伺服器時間與 Foundation 模式；DB／設備／交易固定為 false。
2. `GET /health/live`：程序存活，非 DB、設備或計費 readiness。
3. Development Swagger、統一錯誤與欄位驗證、每次回應 `X-Trace-Id`、明確 CORS origins。
4. Vue `/#/pos` 預覽與 `/#/system` 真實系統資訊 API 連線；開發模式四狀態預覽，正式產物不提供示範切換。
5. 本地設定延續原型 laneName／postCode，忽略原型可編輯 API URL。正式 API base 改由部署環境管理，避免本機顯示設定冒充後端綁定。
6. `.agents/skills` 三個本案 Skills、AGENTS.md、開發索引及啟動文件。
